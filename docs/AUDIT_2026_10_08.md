# High-level project audit — 8 October 2026

This checkpoint audits the implemented Round-1 application. It is evidence of specific checks, not a guarantee that every possible bug or production integration is covered.

## Fixes

- Faculty drilldown now counts the actual supplied source categories, shows recorded engagement and feedback, and uses each student's real demo curriculum. Nursing records no longer show unrelated computer-science subjects with `null/100`. Review explanations use the configured rules instead of old curated prompts.
- Missing or invalid historical measurements are excluded from trend plots, rather than plotted as zero. Invalid student subject marks are excluded from averages. Missing growth values have an explicit empty state.
- Fresh account profiles and PDF reports display an unspecified year/semester instead of the database's zero sentinel.
- Policy approval must be the boolean `true`. Unapproved/invalid policies and absent weights no longer fabricate zero-point contributions. Mixed academic and career flags are placed in the academic-support segment; a high CGPA alone cannot conceal attendance or LMS concerns.
- Empty, malformed and unknown-source AI responses fall back to deterministic English. Cached Gemini responses retain their correct attribution.
- Async management permission and workspace-error responses cannot overwrite a later navigation render.
- Signup progress and confirmation announcements now use signup wording. Dialog titles are escaped once. Source-provided icon names and overview measurement values are HTML-escaped.
- PDF empty-data status colors, summary language, weights and factor labels no longer imply a valid positive score when evidence/rules are absent. Sample reports were regenerated.

No student source measurement, policy weight, account or permission was changed. The corrected mutually exclusive demo segments are 7 strong-academic/career-practice, 147 academic support, 39 career practice, and 307 without triggered checks. Total students needing review remains 193; mean success remains approximately 72.6. Academic flags (147) and career flags (89) overlap and must not be added as a unique-student total.

## Remaining limitations

- Supabase security advisor still reports leaked-password protection disabled. Official documentation states that protection is available on Pro plans and above: https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection . No billing upgrade or Auth security configuration was made. Performance advisor returned no lints.
- Real email delivery, production confirmation redirect settings and a real signed-in Gemini round trip were not verified. Fallback behavior and the function's unauthenticated denial were verified separately.
- Live faculty cohort authorization, live recruiter discovery/consent integration, verified achievement uploads, photo storage and student doubt-ticket services remain pending features. Current role previews/drafts are explicitly synthetic/local.
- Scoring and coupled effort coefficients remain labelled illustrative rules, not validated academic/placement predictions.
- Vercel build-log access returned a connector-scope 403 and no log drains are configured. Browser checks do not establish complete runtime observability.

## Reproduce

Run `npm ci`, `npm test`, `npm run build` and `npm audit` with the supported Node version. Regression cases added in `tests/audit.test.js`. For permission checks, use the rollback-only SQL fixture with an authorized database connection; do not copy account fixtures into persistent production data. Keep all credentials out of source control.
